Abstract
Аннотация
This document proposes an extension to the Session Initiation Protocol (SIP). This extension adds the INFO method to the SIP protocol. The intent of the INFO method is to allow for the carrying of session related control information that is generated during a session. One example of such session control information is ISUP and ISDN signaling messages used to control telephony call services.
Настоящий документ предлагает расширение протокола инициирования сессий (SIP). Это расширение добавляет метод INFO в протокол SIP. Назначение метода INFO — обеспечить передачу управляющей информации, связанной с сессией, которая генерируется в ходе сессии. Одним из примеров такой управляющей информации сессии являются сигнальные сообщения ISUP и ISDN, используемые для управления телефонными услугами вызова.
This and other example uses of the INFO method may be standardized in the future.
Это и другие примеры использования метода INFO могут быть стандартизованы в будущем.
1. Introduction
1. Введение
The SIP protocol described in [1] defines session control messages used during the setup and tear down stages of a SIP controlled session.
Протокол SIP, описанный в [1], определяет сообщения управления сессией, используемые на этапах установления и завершения сессии, управляемой SIP.
In addition, the SIP re-INVITE can be used during a session to change the characteristics of the session. This is generally to change the properties of media flows related to the session or to update the SIP session timer.
Кроме того, в течение сессии может использоваться SIP re-INVITE для изменения характеристик сессии. Как правило, это делается для изменения свойств медиапотоков, связанных с сессией, или для обновления таймера SIP-сессии.
However, there is no general-purpose mechanism to carry session control information along the SIP signaling path during the session.
Однако универсального механизма для передачи информации управления сессией вдоль сигнального пути SIP во время сессии не существует.
The purpose of the INFO message is to carry application level information along the SIP signaling path.
Назначение сообщения INFO — передавать информацию прикладного уровня вдоль сигнального пути SIP.
The INFO method is not used to change the state of SIP calls, or the parameters of the sessions SIP initiates. It merely sends optional application layer information, generally related to the session.
Метод INFO не используется для изменения состояния SIP-вызовов или параметров сессий, инициируемых SIP. Он лишь передаёт необязательную информацию прикладного уровня, как правило связанную с сессией.
It is necessary that the mid-session signaling information traverse the post session setup SIP signaling path. This is the path taken by SIP re-INVITEs, BYEs and other SIP requests that are tied to an individual session. This allows SIP proxy servers to receive, and potentially act on, the mid-session signaling information.
Необходимо, чтобы сигнальная информация, передаваемая в середине сессии, проходила по сигнальному пути SIP, установленному после фазы установления сессии. Это тот же путь, по которому следуют SIP re-INVITE, BYE и другие SIP-запросы, привязанные к отдельной сессии. Это позволяет SIP-прокси-серверам получать сигнальную информацию, передаваемую в середине сессии, и потенциально реагировать на неё.
This document proposes an extension to SIP by defining the new INFO method. The INFO method would be used for the carrying of mid-call signaling information along the session signaling path.
Настоящий документ предлагает расширение SIP, определяя новый метод INFO. Метод INFO должен применяться для передачи сигнальной информации в середине вызова вдоль сигнального пути сессии.
1.1 Example Uses The following are a few of the potential uses of the INFO message:
1.1. Примеры использования. Ниже приведены несколько потенциальных применений сообщения INFO:
- Carrying mid-call PSTN signaling messages between PSTN gateways.
- передача сигнальных сообщений ТфОП в середине вызова между PSTN-шлюзами;
- Carrying DTMF digits generated during a SIP session.
- передача DTMF-цифр, сгенерированных в ходе сессии SIP;
- Carrying wireless signal strength information in support of wireless mobility applications.
- передача информации о силе беспроводного сигнала в поддержку приложений беспроводной мобильности;
- Carrying account balance information.
- передача информации о балансе счёта;
- Carrying images or other non streaming information between the participants of a session.
- передача изображений или другой непоточной информации между участниками сессии.
These are just potential uses; this document does not specify such uses nor does it necessarily recommend them.
Это лишь потенциальные применения; настоящий документ не определяет такие применения и не обязательно рекомендует их.
It can also be envisioned that there will be other telephony and non-telephony uses of the INFO method.
Также можно предположить, что будут и другие телефонные и нетелефонные применения метода INFO.
2. INFO Method
2. Метод INFO
The INFO method is used for communicating mid-session signaling information along the signaling path for the call.
Метод INFO используется для передачи сигнальной информации в середине сессии вдоль сигнального пути вызова.
The INFO method is not used to change the state of SIP calls, nor does it change the state of sessions initiated by SIP. Rather, it provides additional optional information which can further enhance the application using SIP.
Метод INFO не используется для изменения состояния SIP-вызовов и не изменяет состояние сессий, инициированных SIP. Напротив, он предоставляет дополнительную необязательную информацию, которая может расширить возможности приложения, использующего SIP.
The signaling path for the INFO method is the signaling path established as a result of the call setup. This can be either direct signaling between the calling and called user agents or a signaling path involving SIP proxy servers that were involved in the call setup and added themselves to the Record-Route header on the initial INVITE message.
Сигнальный путь для метода INFO — это путь, установленный в результате установления вызова. Это может быть либо прямая сигнализация между вызывающим и вызываемым пользовательскими агентами, либо сигнальный путь с участием SIP-прокси-серверов, которые были задействованы при установлении вызова и добавили себя в заголовок Record-Route исходного сообщения INVITE.
The mid-session information can be communicated in either an INFO message header or as part of a message body. The definition of the message body and/or message headers used to carry the mid-session information is outside the scope of this document.
Информация, передаваемая в середине сессии, может содержаться либо в заголовке сообщения INFO, либо в теле сообщения. Определение тела сообщения и/или заголовков, используемых для передачи информации в середине сессии, выходит за рамки настоящего документа.
There are no specific semantics associated with INFO. The semantics are derived from the body or new headers defined for usage in INFO.
С методом INFO не связана какая-либо конкретная семантика. Семантика определяется телом сообщения или новыми заголовками, определёнными для использования в INFO.

2.4 Behavior of SIP User Agents
2.4. Поведение пользовательских агентов SIP
Unless stated otherwise, the protocol rules for the INFO request governing the usage of tags, Route and Record-Route, retransmission and reliability, CSeq incrementing and message formatting follow those in [1] as defined for the BYE request. An INFO request MAY be cancelled. A UAS receiving a CANCEL for an INFO request SHOULD respond to the INFO with a "487 Request Cancelled" response if a final response has not been sent to the INFO and then behave as if the request were never received. However, the INFO message MUST NOT change the state of the SIP call, or the sessions initiated by SIP.

3. INFO Message Bodies
3. Тела сообщений INFO
The purpose of the INFO message is to carry mid-session information between SIP user agents. This information will generally be carried in message bodies, although it can be carried in headers in the INFO message.
Назначение сообщения INFO — передавать информацию середины сессии между пользовательскими агентами SIP. Как правило, эта информация передаётся в телах сообщений, хотя может передаваться и в заголовках сообщения INFO.
The definition of the message bodies or any new headers created for the INFO method is outside the scope of this document. It is expected that separate documents will be created to address definition of these entities. In addition, the INFO method does not define additional mechanisms for ensuring in-order delivery. While the CSeq header will be incremented upon the transmission of new INFO messages, this should not be used to determine the sequence of INFO information. This is due to the fact that there could be gaps in the INFO message CSeq count caused by a user agent sending re-INVITES or other SIP messages.
Определение тел сообщений или любых новых заголовков, создаваемых для метода INFO, выходит за рамки настоящего документа. Предполагается, что для определения этих сущностей будут созданы отдельные документы. Кроме того, метод INFO не определяет дополнительных механизмов обеспечения доставки в правильном порядке. Хотя заголовок CSeq увеличивается при передаче новых сообщений INFO, это не следует использовать для определения порядка следования информации INFO. Причина в том, что в счётчике CSeq сообщений INFO могут возникать пропуски из-за того, что пользовательский агент отправляет re-INVITE или другие сообщения SIP.
4. Guidelines for extensions making use of INFO
4. Рекомендации для расширений, использующих INFO
The following are considerations that should be taken into account when defining SIP extensions that make use of the INFO method.
Ниже перечислены соображения, которые следует учитывать при определении расширений SIP, использующих метод INFO.
- Consideration should be taken on the size of message bodies to be carried by INFO messages. The message bodies should be kept small due to the potential for the message to be carried over UDP and the potential for fragmentation of larger messages.
— Следует учитывать размер тел сообщений, передаваемых в сообщениях INFO. Тела сообщений следует делать небольшими из-за возможности передачи сообщения по UDP и возможности фрагментации более крупных сообщений.
- There is potential that INFO messages could be forked by a SIP Proxy Server. The implications of this forking of the information in the INFO message need to be taken into account.
— Существует вероятность того, что сообщения INFO могут подвергнуться ветвлению (forking) на SIP-прокси-сервере. Необходимо учитывать последствия такого ветвления информации в сообщении INFO.
- The use of multi-part message bodies may be helpful when defining the message bodies to be carried by the INFO message.
— При определении тел сообщений, передаваемых в сообщении INFO, может оказаться полезным использование составных (multi-part) тел сообщений.
- The extensions that use the INFO message MUST NOT rely on the INFO message to do anything that effects the SIP call state or the state of related sessions.
— Расширения, использующие сообщение INFO, НЕ ДОЛЖНЫ полагаться на сообщение INFO в части выполнения каких-либо действий, влияющих на состояние SIP-вызова или состояние связанных сессий.
- The INFO extension defined in this document does not depend on the use of the Require or Proxy-Require headers. Extensions using the INFO message may need the use of these mechanisms. However, the use of Require and Proxy-Require should be avoided, if possible, in order to improve interoperability between SIP entities.
— Расширение INFO, определённое в настоящем документе, не зависит от использования заголовков Require или Proxy-Require. Расширениям, использующим сообщение INFO, эти механизмы могут понадобиться. Однако во избежание проблем при взаимодействии между объектами SIP использование Require и Proxy-Require следует, по возможности, избегать.
5. Security Considerations
5. Вопросы безопасности
If the contents of the message body are private then end-to-end encryption of the message body can be used to prevent unauthorized access to the content.
Если содержимое тела сообщения является конфиденциальным, для предотвращения несанкционированного доступа к нему можно использовать сквозное шифрование тела сообщения.
There are no other security issues specific to the INFO method. The security requirements specified in the SIP specification apply to the INFO method.
Иных вопросов безопасности, специфичных для метода INFO, нет. Требования безопасности, указанные в спецификации SIP, распространяются и на метод INFO.
