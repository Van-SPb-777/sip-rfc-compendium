# toolkit — инструменты аудита двуязычной вёрстки (RFC)

Переносимый набор скриптов для проверки пар «английский блок / русский
перевод» в пословном (блок-в-блок) двуязычном издании. Пакет вынут из проекта
`rfc-book` (двуязычный сборник RFC), но сами проверки написаны про текст, а не
про RFC: большинство из них применимо к любой параллельной вёрстке
«оригинал слева, перевод справа».

Задача пакета — **находить дефекты разметки и перевода, а не исправлять их**.
Ничего не собирает (PDF/HTML — отдельные инструменты проекта) и по умолчанию
ничего не пишет на диск: все проверки только читают JSON и `.txt`.

---

## 1. Состав пакета

| Файл | Что это |

| `detect_*.py` | 34 детектора; каждый запускается и отдельно, и вызывается из `audit_all.py` |

## 2. Какие данные нужны

### 2.1. Обязательно: JSON блоков

Каталог с файлами `rfc<NNNN>.json`. Один файл — один документ:

```json
{
  "num": 3261,
  "title_en": "SIP: Session Initiation Protocol",
  "title_ru": "Протокол инициирования сессий (SIP)",
  "status": "PROPOSED STANDARD",
  "date": "July 2002",
  "blocks": [
    {"kind": "heading", "en": "1. Introduction", "ru": "1. Введение"},
    {"kind": "prose",   "en": "…английский абзац…", "ru": "…перевод…"},
    {"kind": "code",    "en": "…", "ru": null},
    {"kind": "diagram", "en": "…", "ru": ""}
  ]
}
```

Обязательные поля блока:

| Поле | Смысл |
|---|---|
| `kind` | тип блока: `heading`, `prose`, `prose_cont` — переводятся; `code`, `table`, `diagram`, `abnf`, `sip`, `sdp`, `title` — обычно нет |
| `en` | английский текст блока (источник истины) |
| `ru` | перевод; `null` или `""` — перевода нет |

Необязательные поля, которые учитывают отдельные проверки:
`excluded` (документ вне собрания), `skip_translation` (не переводится),
`skip_length` (не сравнивать длины), `note_ru` (пояснение к непереводимому
блоку), `num` на верхнем уровне.

Каталог по умолчанию — `..\translations` рядом с `toolkit` (см. §4).

### 2.2. Нужно не всем проверкам: исходные `.txt`

Каталог с файлами `rfc<NNNN>.txt` — исходники в формате RFC (ASCII, страницы,
колонтитулы, form feed). Нужны проверкам, которые сверяют `en` с оригиналом:
`original` (6), `broken` (7), `paracount`, `linebreak`, `mergepara`,
`headlost`, `figsplit`, `diagsplit`, `colspace`, `preamble`, `gap`.
Каталог по умолчанию — `..\rfc-sip` (см. §4).

Если каталога нет, эти проверки не падают, а **молча пропускаются** (ловят
`OSError`/проверяют `os.path.exists`). Поэтому «0 находок» без исходников
означает «не проверялось», а не «чисто».

### 2.3. Запись на диск

Пакет только читает. Единственное место, которое пишет, — `store.save()`
(вызывается только вручную, аудитом не используется). Проверки PDF/HTML в
пакет не входят.

## 3. Запуск

```bat
python audit_all.py 3261              :: один документ
python audit_all.py 3261 3265 5806    :: несколько
python audit_all.py                   :: все rfc*.json из каталога переводов
python audit_all.py --fast 3261       :: только дешёвые проверки (без сверки с .txt)
```

Код возврата: `0` — замечаний нет, `1` — есть находки (годится для CI).

Пример вывода по чистому документу (строка `RFC 3261 …` печатается только
когда у документа есть находки):

```
К сведению (не блокирует сборку):
  подозрений на дубль (в т.ч. в начале блока): 4
  блоков с потерянными числами      : 7

====================================================================
ИТОГО по 0 документам с замечаниями
  missing   0
  short     0
  …
  secnum    0
====================================================================
```

Отдельный детектор:

```bat
python detect_spill.py 3261
python detect_broken.py 3261
python detect_colspace.py 3261,3265
python detect_artifacts.py            :: все документы
```

Большинство детекторов принимает `N` или `N,N,...`, без аргумента обходит весь
каталог переводов и возвращает код 1 при находках. Часть детекторов
(`paracount`, `linebreak`, `dupnext`, `gap`, `lossy`, `cross_dupe`,
`numbers`) в `audit_all.py` не входит — см. §6.

## 4. Пути: как пакет находит данные

Абсолютных путей к проекту в файлах нет. Все пути вычисляются:

| Переменная | Значение по умолчанию | Переопределение |
|---|---|---|
| `BASE` | каталог, где лежит `audit_all.py` (сам `toolkit`) | — |
| `RFC_TRANS` | `..\translations`, иначе `.\translations` | переменная окружения `RFC_TRANS` |
| `RFC_SRC` | `..\rfc-sip`, если его нет — `..\..\rfc-sip` | переменная окружения `RFC_SRC` |

Проверка порядка для `RFC_SRC`: если задана переменная окружения — берётся она
(без проверки существования); иначе первый существующий из двух кандидатов;
если нет ни одного — `..\rfc-sip` (и зависящие от `.txt` проверки
пропускаются).

Примеры:

```bat
:: Windows, разовая установка на сеанс
set RFC_SRC=D:\data\rfc-sip
set RFC_TRANS=D:\data\translations
python audit_all.py 3261
```

```powershell
$env:RFC_SRC = "D:\data\rfc-sip"
$env:RFC_TRANS = "D:\data\translations"
python audit_all.py 3261
```

Типовая раскладка, при которой ничего настраивать не нужно:

```
project\
  translations\rfc3261.json ...   <- RFC_TRANS = ..\translations
  rfc-sip\rfc3261.txt ...         <- RFC_SRC   = ..\rfc-sip
  toolkit\audit_all.py ...
```

Если `toolkit` лежит глубже (как в исходном проекте: `rfc-book\toolkit`, а
исходники в соседнем `test_ai\rfc-sip`), сработает второй кандидат
`..\..\rfc-sip`.

## 5. Что именно проверяется

### 5.1. Универсальные проверки двуязычной вёрстки

Не зависят от RFC: работают на любой параллельной вёрстке «блок EN / блок RU».

* полнота перевода (`missing`), обрыв (`short`) и раздутие (`long`) по длине;
* чужой текст — маркеры лексики, которой нет в своём `en` (`foreign`);
* обрезанный перевод посреди фразы (`cut`) и сдвиг границ (`shift`);
* залезший в блок перевод соседнего абзаца (`spill`), лишние предложения
  (`extrasent`), повтор фразы (`dupphrase`);
* дубли: в начале блока (`duphead`), блок целиком (`dupblock`), два одинаковых
  блока подряд (`dupnext`), перевод одного абзаца в двух блоках
  (`cross_dupe`);
* склейка двух абзацев в один блок (`mergepara`) и, наоборот, число абзацев
  внутри блока не совпало с оригиналом (`paracount`);
* потерянные переводы строк (`linebreak`), список вклеен в абзац
  (`inlinelist`), список размечен как код (`codelist`);
* потерянный хвост-анонс с двоеточием (`tail`);
* разорванное переносом слово (`hyphsplit`);
* повтор слова (`dupword`), регистр URI (`urlcase`), скобки (`paren`),
  смешение алфавитов (`script`), перевод внутри непереводимого блока
  (`coderu`), «тихая» потеря (`lossy`), пропавший раздел (`gap`).

### 5.2. Специфичные для RFC

Привязаны к формату RFC (страницы, колонтитулы, ASCII-графика, нумерация
разделов, ABNF, SIP) или к формату хранения блоков этого проекта:

* сверка `en` с исходным `.txt` дословно (`original`);
* ложный заголовок / обрыв на ссылке / слипшийся абзац (`broken`);
* номер в заголовке не совпал с оригиналом (`headnum`);
* псевдографика: в прозе или разрезана (`figsplit`, `diagsplit`), сплющена
  (`squeeze`), схлопнуты пробелы колонок (`colspace`);
* структура (ABNF/таблица/пример SIP) внутри прозы (`structure`), обычный
  текст в блоке «код» (`textcode`), пример SIP слипся в абзац (`example`);
* поля формы IANA / «Authors' Addresses» склеены (`form`);
* остатки оглавления (`toc`), оформление начала документа — шапка + `title`
  (`preamble`), заголовок потерял тип (`headlost`);
* артефакты: колонтитулы, form feed, BOM (`artifacts`);
* номер «раздела» в переводе против `Section N` в оригинале (`secnum`);
* потерянные числа (`numbers`, информационная).

Часть проверок из «специфичных» легко переносится на другой формат: `preamble`
и `artifacts` — это просто «шапка документа» и «мусорные символы»; пороги и
шаблоны в них меняются в одном месте.

### 5.3. Нумерация проверок

Номера — те же, что в `ДЕФЕКТЫ.md` и в комментариях `audit_all.py`
(1–40). В шапке-докстроке `audit_all.py` сохранилась старая нумерация первых
версий: «10. ПОВТОР», «11. URL», «12. СКОБКИ», «13. АЛФАВИТ», «14. РАЗДЕЛ» —
это сегодняшние 35, 36, 37, 38, 39.

36 счётчиков печатаются в сводке. Ещё четыре проверки существуют, но в сводку
не выведены (см. §8): `dupphrase` (39), `coderu` (40), `cross_dupe`,
`numbers` — последние две учитываются отдельными строками «К сведению».

## 6. Как добавить свою проверку

1. Создайте рядом с `audit_all.py` файл `detect_mycheck.py` по шаблону:

```python
# -*- coding: utf-8 -*-
"""ПРОВЕРКА mycheck: что ищем — одной строкой."""
import os
import sys

BASE = os.path.dirname(os.path.abspath(__file__))
sys.path.insert(0, BASE)
import store


def scan(num):
    """Вернуть список номеров блоков с дефектом (или кортежей)."""
    obj = store.load(num)
    if not obj or obj.get("excluded") or obj.get("skip_translation"):
        return []
    out = []
    for i, b in enumerate(obj["blocks"]):
        if b.get("kind") not in ("prose", "prose_cont"):
            continue
        en = b.get("en") or ""
        ru = b.get("ru") or ""
        if <ваше условие>:
            out.append(i)
    return out


if __name__ == "__main__":
    args = [a for a in sys.argv[1:] if not a.startswith("--")]
    nums = ([int(a) for a in args[0].split(",")] if args
            else store.status_report())
    total = 0
    for n in nums:
        hits = scan(n)
        if hits:
            print("RFC %-5d mycheck: %d %s" % (n, len(hits), hits[:8]))
            total += len(hits)
    print("ИТОГО: %d" % total)
    sys.exit(1 if total else 0)
```

2. Проверьте на одном документе: `python detect_mycheck.py 3261`. Убедитесь,
   что на заведомо чистом блоке находок нет, а на испорченном — есть
   (подставьте синтетический объект вроде
   `{"blocks": [{"kind": "prose", "en": "...", "ru": "..."}], ...}`).
3. Встройте в `audit_all.py` — правок ровно четыре:
   * ключ в словарь `res` (строка ~242): `"mycheck": [],`;
   * блок вызова в `audit()` после остальных:
     ```python
     try:
         import detect_mycheck
         for i in detect_mycheck.scan(num):
             res["mycheck"].append(i)
     except ImportError:
         pass
     ```
   * ключ в словарь `totals` в `main()` (строка ~661) и в строку формата
     вывода, иначе находки не попадут в итог;
   * строку печати `for i in r["mycheck"][:8]: ...`.
4. Прогоните `python audit_all.py 3261` и сравните: остальные счётчики не
   должны измениться.

Важно: если добавить ключ в `res`, но не добавить его в `totals`/формат,
проверка будет работать «в стол» — именно так в проекте оказались
`dupphrase` и `coderu`. Если добавить ключ в `totals`, но не в `res`, аудит
упадёт с `KeyError` на первом же документе.

## 8. Ограничения

1. **Это эвристики, а не доказательства.** Пороги подобраны на библиотеке
   RFC и дают ложные срабатывания. По отчётам проекта: `extrasent` показывал
   674 записи, реальных заносов оказалось 21; `spill` — 181 запись, реальных
   дефектов 25. Находку надо смотреть глазами, а не чинить массово.
2. **Проверка 4 (`dupe`) отключена** осознанно: надёжного критерия без ложных
   срабатываний не нашлось (`has_dupe()` всегда `False`).
3. **`dupphrase` и `coderu` не выводятся** в сводке `audit_all.py`: находки
   складываются в `res["dupphrase"]` (ключ не входит в `totals`/формат), а
   `res["coderu"]` вообще не заведён — `KeyError` глушится `except Exception`.
   Обе проверки можно вызвать вручную:
   `python -c "import detect_dupword; print(detect_dupword.scan_phrases(3261))"`;
   логика `coderu` — в `audit_all.py`, строки 367–378.
4. **Без каталога `.txt`** проверки, сверяющиеся с исходником, молча
   пропускаются: «0» в них означает «не проверялось».
5. **Только текст.** Пакет не проверяет вёрстку PDF/HTML, шрифты, разрывы
   страниц, колонки — это отдельный слой проекта (сборщики в пакет не входят).
6. **Только обнаружение.** Один скопированный модуль содержит и функцию-фиксер
   исходного проекта: `detect_diagsplit.merge()` склеивает разрезанную схему и
   вызывает `store.save()` — то есть **пишет JSON**. В пакете она не
   вызывается (аудит её не использует), но при ручном вызове меняет данные;
   перед таким вызовом делайте резервную копию.
7. **Пути к `.txt`** в нескольких детекторах собираются как
   `"%s\\rfc%d.txt" % (SRC, num)` — это Windows-разделитель. На Windows
   работает, на POSIX потребуется замена на `os.path.join`.
8. **Флаги данных.** Блоки с `excluded`/`skip_translation` пропускаются;
   `skip_length` отключает сравнение длин; заголовки не сравниваются по длине
   (разная длина при одинаковом смысле).
9. **Счётчики информационные.** `cross_dupe` и `numbers` намеренно не входят в
   блокирующие: у них много законных срабатываний.
10. **Пять детекторов не входят в `audit_all.py`**: `paracount`,
    `linebreak`, `dupnext`, `gap`, `lossy`. Они запускаются отдельно; в
    исходном проекте так и было.

## 9. Отличия от исходного проекта

Логика проверок не менялась. Изменено только то, что мешало переносу:

* `sys.path.insert(0, r"C:\...\rfc-book")` → `BASE = os.path.dirname(os.path.abspath(__file__))`
  и `sys.path.insert(0, BASE)`;
* удалён `sys.path.insert(0, r"C:\...\test_ai")` — `rfc_parse.py` теперь лежит
  рядом;
* `SRC = r"C:\...\rfc-sip"` / `SRC_DIR` / `D` / путь в `_cs_lib.py` →
  вычисление от `BASE` с переменной окружения `RFC_SRC`;
* склейка `"%s\\rfc%d.txt" % (SRC, num)` и литерал в `audit_all.py` →
  `os.path.join(SRC, "rfc%d.txt" % num)`;
* `store.py` переписан на относительные пути (API прежний: `load`, `save`,
  `path_for`, `is_done`, `status_report`);
* добавлены `rfc_parse.py`, `_cs_lib.py`, `_cs_match.py` — без них часть
  детекторов не импортируется;
* в шапку `audit_all.py` добавлен комментарий про `BASE`/`RFC_SRC`/`RFC_TRANS`
  (код не затронут).

Файлы проекта (`translations/*.json`, `.txt`, отчёты, сборщики) не изменялись:
пакет собран копированием.
