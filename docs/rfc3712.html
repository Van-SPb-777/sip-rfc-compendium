Abstract
Аннотация
This document defines a schema, object classes and attributes, for printers and printer services, for use with directories that support Lightweight Directory Access Protocol v3 (LDAP-TS). This document is based on the printer attributes listed in Appendix E of Internet Printing Protocol/1.1 (IPP) (RFC 2911). A few additional printer attributes are based on definitions in the Printer MIB (RFC 1759).
Этот документ определяет схему, классы объектов и атрибуты для принтеров и служб печати для использования с каталогами, поддерживающими протокол облегчённого доступа к каталогам версии 3 (LDAP-TS). Этот документ основан на атрибутах принтера, перечисленных в приложении E к Internet Printing Protocol/1.1 (IPP) (RFC 2911). Несколько дополнительных атрибутов принтера основаны на определениях из Printer MIB (RFC 1759).
1. Introduction
1. Введение
This document defines several object classes to provide Lightweight Directory Access Protocol v3 [LDAP-TS] applications with flexible options in defining printer information using LDAP schema. Classes are provided for defining directory entries with common printer information as well as for extending existing directory entries with SLPv2 [RFC2608], IPP/1.1 [RFC2911], and LPR [RFC1179] specific information.
Этот документ определяет несколько классов объектов, чтобы предоставить приложениям протокола облегчённого доступа к каталогам версии 3 [LDAP-TS] гибкие возможности при определении информации о принтере с помощью схемы LDAP. Классы предусмотрены как для определения записей каталога с общей информацией о принтере, так и для расширения существующих записей каталога сведениями, специфичными для SLPv2 [RFC2608], IPP/1.1 [RFC2911] и LPR [RFC1179].
The schema defined in this document is based on the printer attributes listed in Appendix E 'Generic Directory Schema' of Internet Printing Protocol/1.1 (IPP) [RFC2911]. A few additional printer attributes are based on definitions in the Printer MIB [RFC1759].
Схема, определённая в этом документе, основана на атрибутах принтера, перечисленных в приложении E «Generic Directory Schema» к Internet Printing Protocol/1.1 (IPP) [RFC2911]. Несколько дополнительных атрибутов принтера основаны на определениях из Printer MIB [RFC1759].
The schema defined in this document is technically aligned with the stable IANA-registered 'service:printer:' v2.0 template [SLP-PRT], for compatibility with already deployed Service Location Protocol (SLPv2) [RFC2608] service advertising and discovery infrastructure. The attribute syntaxes are technically aligned with the 'service:printer:' v2.0 template - therefore simpler types are sometimes used (for example, 'DirectoryString' [RFC2252] rather than 'labeledURI' [RFC2079] for the 'printer-uri' attribute).
Схема, определённая в этом документе, технически согласована со стабильным шаблоном 'service:printer:' v2.0, зарегистрированным в IANA [SLP-PRT], для совместимости с уже развёрнутой инфраструктурой объявления и обнаружения служб Service Location Protocol (SLPv2) [RFC2608]. Синтаксисы атрибутов технически согласованы с шаблоном 'service:printer:' v2.0, поэтому иногда используются более простые типы (например, 'DirectoryString' [RFC2252] вместо 'labeledURI' [RFC2079] для атрибута 'printer-uri').

1.2. Rationale for using caseIgnoreMatch

1) URI
1) URI.
These URI attributes specify EQUALITY matching with 'caseIgnoreMatch' (rather than with 'caseExactMatch') in order to conform to the spirit of [RFC2396], which requires case insensitive matching on the host part of a URI versus case sensitive matching on the remainder of a URI.
Эти атрибуты URI задают сопоставление EQUALITY с 'caseIgnoreMatch' (а не с 'caseExactMatch'), чтобы соответствовать духу [RFC2396], который требует нечувствительного к регистру сопоставления для хостовой части URI в отличие от чувствительного к регистру сопоставления для остальной части URI.
These URI attributes follow existing practice of supporting case insensitive equality matching for host names in the associatedDomain attribute defined in [RFC1274].
Эти атрибуты URI следуют существующей практике поддержки нечувствительного к регистру сопоставления равенства для имён хостов в атрибуте associatedDomain, определённом в [RFC1274].
Either equality matching rule choice would be a compromise: a) case sensitive whole URI matching may lead to false negative matches and has been shown to be fragile (given deployed client applications that 'pretty up' host names displayed and transferred in URI); b) case insensitive whole URI matching may lead to false positive matches, although it is a dangerous practice to publish URI that differ only by case (for example, in the path elements).
Любой выбор правила сопоставления равенства был бы компромиссом: a) чувствительное к регистру сопоставление всего URI может приводить к ложным отрицательным совпадениям и, как показано, является хрупким (учитывая развёрнутые клиентские приложения, которые «приукрашивают» имена хостов, отображаемые и передаваемые в URI); b) нечувствительное к регистру сопоставление всего URI может приводить к ложным положительным совпадениям, хотя публикация URI, различающихся только регистром (например, в элементах пути), является опасной практикой.
2) Description Case insensitive equality matching is more user-friendly for description attributes.
2) Описание. Нечувствительное к регистру сопоставление равенства более удобно для пользователя применительно к описательным атрибутам.
3) Keyword Case insensitive equality matching is more user-friendly for keyword attributes.
3) Ключевое слово. Нечувствительное к регистру сопоставление равенства более удобно для пользователя применительно к атрибутам ключевых слов.

9. Security Considerations
9. Вопросы безопасности
See [RFC2829] for detailed guidance on authentication methods for LDAP. See [RFC2830] for detailed guidance of using TLS/1.0 [RFC2246] to supply connection confidentiality and data integrity for LDAP sessions.
См. [RFC2829] для подробных указаний по методам аутентификации для LDAP. См. [RFC2830] для подробных указаний по использованию TLS/1.0 [RFC2246] для обеспечения конфиденциальности соединения и целостности данных для сеансов LDAP.
As with any LDAP schema, it is important to protect specific entries and attributes with the appropriate access control. It is particularly important that only administrators can modify entries defined in this LDAP printer schema. Otherwise, an LDAP client might be fooled into diverting print service requests from the original printer (or spooler) to a malicious intruder's host system, thus exposing the information in printed documents.
Как и в случае любой схемы LDAP, важно защищать конкретные записи и атрибуты с помощью соответствующего контроля доступа. Особенно важно, чтобы только администраторы могли изменять записи, определённые в этой схеме принтера LDAP. В противном случае клиент LDAP может быть обманут и перенаправит запросы службы печати от исходного принтера (или спулера) на хост-систему злонамеренного нарушителя, тем самым раскрыв информацию в напечатанных документах.
For additional security considerations of deploying printers in an IPP environment, see Section 8 of [RFC2911].
Дополнительные вопросы безопасности развёртывания принтеров в среде IPP см. в разделе 8 [RFC2911].
