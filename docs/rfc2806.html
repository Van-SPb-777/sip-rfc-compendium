Abstract
Аннотация
This document specifies URL (Uniform Resource Locator) schemes "tel", "fax" and "modem" for specifying the location of a terminal in the phone network and the connection types (modes of operation) that can be used to connect to that entity. This specification covers voice calls (normal phone calls, answering machines and voice messaging systems), facsimile (telefax) calls and data calls, both for POTS and digital/mobile subscribers.
Настоящий документ определяет схемы URL (Uniform Resource Locator) «tel», «fax» и «modem» для указания местоположения терминала в телефонной сети и определения того, как с ним можно связаться. Схема «tel» описывает подключение к терминалу, который обрабатывает обычные голосовые звонки или службы. Схема «fax» описывает подключение к терминалу, который может обрабатывать телефаксы.
1. Introduction
1. Введение
1.1. New URL schemes
1.1. Новые схемы URL
This specification defines three new URL schemes: "tel", "fax" and "modem". They are intended for describing a terminal that can be contacted using the telephone network. The description includes the subscriber (telephone) number of the terminal and the necessary parameters to be able to successfully connect to that terminal.
Настоящая спецификация определяет три новые схемы URL: «tel», «fax» и «modem». Они предназначены для описания терминала, с которым можно связаться по телефонной сети. Описание включает абонентский (телефонный) номер терминала и необходимые параметры для успешного подключения к этому терминалу.
The "tel" scheme describes a connection to a terminal that handles normal voice telephone calls, a voice mailbox or another voice messaging system or a service that can be operated using DTMF tones.
Схема «tel» описывает соединение с терминалом, обслуживающим обычные голосовые телефонные вызовы, голосовой почтовый ящик или иную систему голосовых сообщений либо службу, управляемую тонами DTMF.
The "fax" scheme describes a connection to a terminal that can handle telefaxes (facsimiles). The name (scheme specifier) for the URL is "fax" as recommended by [E.123].
Схема «fax» описывает соединение с терминалом, способным принимать телефаксы (факсимильные сообщения). Имя (спецификатор схемы) для URL — «fax», как рекомендовано в [E.123].
The "modem" scheme describes a connection to a terminal that can handle incoming data calls. The term "modem" refers to a device that does digital-to-analog and analog-to-digital conversions; in addition to these, a "modem" scheme can describe a fully digital connection.
Схема «modem» описывает соединение с терминалом, способным принимать входящие вызовы передачи данных. Термин «модем» относится к устройству, выполняющему цифро-аналоговые и аналого-цифровые преобразования; помимо них, схема «modem» может описывать полностью цифровое соединение.
The notation for phone numbers is the same which is specified in [RFC2303] and [RFC2304]. However, the syntax definition is a bit different due to the fact that this document specifies URLs whereas [RFC2303] and [RFC2304] specify electronic mail addresses. For example, "/" (used in URLs to separate parts in a hierarchical URL [RFC2396]) has been replaced by ";". In addition, this URL scheme has been synchronized with [RFC2543]. When these URLs are used, the number of parameters should be kept to the minimum, unless this would make the context of use unclear. Having a short URL is especially important if the URL is intended to be shown to the end user, printed, or otherwise distributed so that it is visible.
Нотация для телефонных номеров та же, что определена в [RFC2303] и [RFC2304]. Однако определение синтаксиса немного отличается из-за того, что настоящий документ определяет URL, тогда как [RFC2303] и [RFC2304] определяют адреса электронной почты. Например, «/» (используется в URL для разделения частей иерархического URL [RFC2396]) заменён на «;». Кроме того, эта схема URL синхронизирована с [RFC2543]. При использовании этих URL число параметров следует держать минимальным, если только это не сделает контекст использования неясным. Наличие короткого URL особенно важно, если URL предназначен для показа конечному пользователю, печати или иного распространения так, чтобы он был виден.

1.2. Формальные определения
The ABNF (augmented Backus-Naur form) notation used in formal definitions follows [RFC2234]. This specification uses elements from the 'core' definitions (Appendix A of [RFC2234]). Some elements have been defined in previous RFCs. If this is the case, the RFC in question has been referenced in comments.
Используемая в формальных определениях нотация ABNF (расширенная форма Бэкуса — Наура) соответствует [RFC2234]. Настоящая спецификация использует элементы из «ядерных» определений (Приложение A [RFC2234]). Некоторые элементы были определены в предыдущих RFC. В этом случае рассматриваемый RFC был указан в комментариях.
Note on non-unreserved characters [RFC2396] in URLs: the ABNF in this document specifies strings of raw, unescaped characters. If those characters are present in a URL, and are not unreserved [RFC2396], they MUST be escaped as explained in [RFC2396] prior to using the URL. In addition, when parsing a URL, it must be noted that some characters may have been escaped.
Примечание о не незарезервированных символах [RFC2396] в URL: ABNF в настоящем документе задаёт строки необработанных, неэкранированных символов. Если эти символы присутствуют в URL и не являются незарезервированными [RFC2396], они ДОЛЖНЫ быть экранированы, как объяснено в [RFC2396], до использования URL.
An example: ABNF notation "%x20" means a single octet with a hexadecimal value of "20" (in US-ASCII, a space character). This must be escaped in a URL, and it becomes "%20".
Пример: нотация ABNF «%x20» означает один октет с шестнадцатеричным значением «20» (в US-ASCII — символ пробела). В URL он должен быть экранирован и становится «%20».
In addition, the ABNF in this document only uses lower case. The URLs are case-insensitive (except for the <future-extension> parameter, whose case-sensitivity is application-specific).
Кроме того, ABNF в настоящем документе использует только нижний регистр. URL нечувствительны к регистру (за исключением параметра <future-extension>, чувствительность которого к регистру зависит от приложения).

2. URL schemes for telephone calls
2. Схемы URL для телефонных вызовов
2.1. Applicability
2.1. Применимость
In this document, "local entity" means software and hardware that can detect and parse one or more of these URLs and possibly place a call to a remote entity, or otherwise utilize the contents of the URL.
В настоящем документе «локальный объект» означает программное и аппаратное обеспечение, способное обнаруживать и разбирать один или несколько таких URL и, возможно, устанавливать соединение с удалённым объектом или иным образом использовать содержимое URL.
These URL schemes are used to direct the local entity to place a call using the telephone network, or as a method to transfer or store a phone number plus other relevant data. The network in question may be a landline or mobile phone network, or a combination of these. If the phone network differentiates between (for example) voice and data calls, or if the local entity has several different telecommunications equipment at its disposal, it is possible to specify which kind of call (voice/fax/data) is requested. The URL can also contain information about the capabilities of the remote entity, so that the connection can be established successfully.
Эти схемы URL используются для указания локальному объекту установить соединение по телефонной сети либо как способ передачи или хранения телефонного номера вместе с другими соответствующими данными. Речь идёт о сети фиксированной или мобильной телефонной связи либо их комбинации. Если телефонная сеть различает (например) голосовые вызовы и вызовы передачи данных либо если локальный объект располагает несколькими различными средствами электросвязи, можно указать, какой вид вызова (голосовой/факсимильный/передачи данных) запрашивается. URL также может содержать информацию о возможностях удалённого объекта, чтобы соединение могло быть успешно установлено.
The "tel", "fax" and "modem" URL schemes defined here do not use the hierarchical URL syntax; there are no applicable relative URL forms. The URLs are always case-insensitive, except for the <future- extension> parameter (see below), whose case-sensitivity is application specific. Characters in the URL MUST be escaped when needed as explained in [RFC2396].
Определённые здесь схемы URL «tel», «fax» и «modem» не используют иерархический синтаксис URL; применимых относительных форм URL нет. URL всегда нечувствительны к регистру, за исключением параметра <future-extension> (см. ниже), чувствительность которого к регистру зависит от приложения.

The URL starts with <telephone-scheme>, which tells the local entity that what follows is a URL that should be parsed as described in this document. After that, the URL contains the phone number of the remote entity. Phone numbers can also contain subaddresses, which are used to identify different remote entities under the same phone number. If a subaddress is present, it is appended to the phone number after ";isub=". Phone numbers can also contain a post-dial sequence. This is what is often used with voice mailboxes and other services that are controlled by dialing numbers from your phone keypad while the call is in progress. The <post-dial> sequence describes what and when the local entity should send to the phone line.
URL начинается с <telephone-scheme>, который сообщает локальному объекту, что далее следует URL, который нужно разобрать, как описано в настоящем документе. После этого URL содержит телефонный номер удалённого объекта. Телефонные номера также могут содержать субадреса, которые используются для идентификации разных удалённых объектов под одним телефонным номером. Если субадрес присутствует, он добавляется к телефонному номеру после «;isub=». Телефонные номера также могут содержать последовательность постдозвона. Это то, что часто используется с голосовыми почтовыми ящиками и другими службами, управляемыми набором цифр с клавиатуры телефона во время вызова. Последовательность <post-dial> описывает, что и когда локальный объект должен передать в телефонную линию.
Phone numbers can be either "global" or "local". Global numbers are unambiguous everywhere. Local numbers are usable only within a certain area, which is called "context", see section 2.5.2.
Телефонные номера могут быть «глобальными» или «локальными». Глобальные номера однозначны повсюду. Локальные номера пригодны к использованию только в определённой области, которая называется «контекстом», см. раздел 2.5.2.
Local numbers always have an <area-specifier>, which specifies the context in which the number is usable (the same number may have different interpretation in different network areas). The context can be indicated with three different prefixes. A <global-network-prefix> indicates that the number is valid within a numbering area whose global numbers start with <global-network-prefix>. Similarly, <local-network-prefix> means that the number is valid within a numbering area whose numbers (or dial strings) start with it. A <private-prefix> is a name of a context. The local entity must have knowledge of this private context to be able to deduce whether it can use the number, see section 2.5.2. Additional information about the phone number's usage can be included by adding the name of the telephony services provider in <service-provider>, see section 2.5.10.
Локальные номера всегда имеют <area-specifier>, который задаёт контекст, в котором номер пригоден (один и тот же номер может иметь разную интерпретацию в разных сетевых областях). Контекст может быть указан тремя разными префиксами. <global-network-prefix> указывает, что номер действителен в области нумерации, глобальные номера которой начинаются с <global-network-prefix>. Аналогично <local-network-prefix> означает, что номер действителен в области нумерации, номера (или наборные строки) которой начинаются с него. <private-prefix> — это имя контекста. Локальный объект должен знать этот частный контекст, чтобы иметь возможность определить, может ли он использовать номер, см. раздел 2.5.2. Дополнительная информация об использовании телефонного номера может быть включена путём добавления имени поставщика услуг телефонии в <service-provider>, см. раздел 2.5.10.
The <future-extension> mechanism makes it possible to add new parameters to this URL scheme. See section 2.5.11.
Механизм <future-extension> позволяет добавлять в эту схему URL новые параметры. См. раздел 2.5.11.
The <private-prefix>, <token-char> and <quoted-string> nonterminals may seem a bit complex at first, but they simply describe the set of octets that are legal in those nonterminals. Some octets may have to be escaped, see [RFC2396].
Нетерминалы <private-prefix>, <token-char> и <quoted-string> могут поначалу показаться несколько сложными, но они просто описывают набор октетов, допустимых в этих нетерминалах. Некоторые октеты могут требовать экранирования, см. [RFC2396].

2.5. Parsing telephone, fax and modem URLs
2.5. Разбор URL tel, fax и modem
2.5.1. Call type
2.5.1. Тип вызова
The type of call is specified by the scheme specifier. "Tel" means that a voice call is opened. "Fax" indicates that the call should be a facsimile (telefax) call. "Modem" means that it should be a data call. Not all networks differentiate between the types of call; in this case, the scheme specifier indicates the telecommunications equipment type to use.
Тип вызова задаётся спецификатором схемы. «Tel» означает, что устанавливается голосовой вызов. «Fax» указывает, что вызов должен быть факсимильным (телефаксным). «Modem» означает, что это должен быть вызов передачи данных. Не все сети различают типы вызова; в этом случае спецификатор схемы указывает тип телекоммуникационного оборудования, который следует использовать.
2.5.2. Phone numbers and their scope
2.5.2. Телефонные номера и их область действия
<telephone-subscriber> and <fax-subscriber> indicate the phone number to be dialed. The phone number can be written in either international or local notation. All phone numbers SHOULD always be written in the international form if there is no good reason to use the local form.
<telephone-subscriber> и <fax-subscriber> указывают телефонный номер, который следует набрать. Телефонный номер может быть записан в международной или локальной нотации. Все телефонные номера СЛЕДУЕТ всегда записывать в международной форме, если нет веской причины использовать локальную форму.
Not all numbers are valid within all numbering areas. The <area- specifier> parameter, which is mandatory for local numbers, is used to indicate the locale within which this number is valid, or to qualify the phone number so that it may be used unambiguously. The <area-specifier> can take three forms: <global-network-prefix>, <local-network-prefix> or <private-prefix>. These are used to describe the validity area of the phone number either in global numbering plan, local numbering plan, or in a private numbering plan, respectively.
Не все номера действительны во всех областях нумерации. Параметр <area-specifier>, обязательный для локальных номеров, используется для указания местности, в пределах которой этот номер действителен, либо для уточнения телефонного номера так, чтобы его можно было использовать однозначно. <area-specifier> может принимать три формы: <global-network-prefix>, <local-network-prefix> или <private-prefix>. Они используются для описания области действия телефонного номера соответственно в глобальном плане нумерации, локальном плане нумерации или частном плане нумерации.
If <area-specifier> is present, the local entity MUST NOT attempt to call out using the phone number if it cannot originate the call within the specified locale. If a <local-phone-number> is used, an <area-specifier> MUST be included as well.
Если <area-specifier> присутствует, локальный объект НЕ ДОЛЖЕН пытаться выполнить вызов с использованием телефонного номера, если он не может инициировать вызов в указанной местности. Если используется <local-phone-number>, то ДОЛЖЕН быть включён и <area-specifier>.
There can be multiple instances of <area-specifier>. In this case, the number is valid in all of the given numbering areas.
Может быть несколько экземпляров <area-specifier>. В этом случае номер действителен во всех указанных областях нумерации.
The global prefix form is intended to act as the outermost context for a phone number, so it will start with a "+", followed by some part of an E.164 number. It also specifies the region in which the phone number is valid. For example, if <global-network-prefix> is "+358", the given number is valid only within Finland (country code 358) - even if it is a <global-phone-number>.
Форма глобального префикса предназначена для использования в качестве внешнего контекста телефонного номера, поэтому она начинается с «+», за которым следует часть номера E.164. Она также указывает регион, в котором телефонный номер действителен. Например, если <global-network-prefix> равен «+358», то указанный номер действителен только в пределах Финляндии (код страны 358), даже если это <global-phone-number>.
The local prefix form is intended to act as an intermediate context in those situations where the outermost context for a phone number is given by another means. One example of use is where the local entity is known to originate calls only within the North American Number Plan Area, so an "outermost" phone context can be assumed. The local context could, for example, be used to indicate the area code within which an associated phone number is situated. Thus "tel:456- 7890;phone-context=213" would suffice to deliver a call to the telephone number "+1-213-456-7890". Note that the version including the <phone-context> implies further that the call can only be originated within the "area code 213" region.
Форма локального префикса предназначена для использования в качестве промежуточного контекста в тех ситуациях, когда внешний контекст телефонного номера задаётся иным способом. Один из примеров использования — когда известно, что локальный объект инициирует вызовы только в пределах Североамериканского плана нумерации, так что «внешний» телефонный контекст можно предположить. Локальный контекст может, например, использоваться для указания кода области, в которой находится соответствующий телефонный номер. Таким образом, «tel:456-7890;phone-context=213» было бы достаточно для доставки вызова на телефонный номер «+1-213-456-7890». Обратите внимание, что версия, включающая <phone-context>, дополнительно подразумевает, что вызов может быть инициирован только в регионе «код области 213».
The <private-prefix> form is intended for use in those situations where the context cannot be expressed with a start of a global phone number or a dialing string. The <private-prefix> is actually a name of a private context. The creator of the URL and the local entity have been configured to recognize this name, and as such they can interpret the number and know how they can utilize the number. For example, a private network numbering plan may be indicated by the name "X-COMPANY-NET", but the private dialling plan from the locales of the sender of the telephony URL and the local entity are different. The syntax of these tokens will be left for future specification. The ABNF above specifies the accepted characters that can be a part of <private-prefix>. Unless the sender is absolutely sure that they share the same private network access digit string with the local entity, then they MUST NOT use a dialling plan number (a local phone number, or one qualified by a local context), as the result may be incorrect. Instead, they SHOULD use a global number, or if that is not possible, a private context as the last resort. If the local entity does not support dialling into the private network indicated by that context, then the request MUST be rejected. If it does, then it will use the access digit string appropriate for its locale.
Форма <private-prefix> предназначена для использования в тех ситуациях, когда контекст не может быть выражен началом глобального телефонного номера или наборной строки. <private-prefix> фактически является именем частного контекста. Создатель URL и локальный объект были настроены на распознавание этого имени, и как таковые они могут интерпретировать номер и знать, как его использовать. Например, план нумерации частной сети может обозначаться именем «X-COMPANY-NET», но частные планы набора из местоположений отправителя телефонного URL и локального объекта различаются. Синтаксис этих лексем оставлен для будущей спецификации. Приведённый выше ABNF задаёт допустимые символы, которые могут быть частью <private-prefix>. Если только отправитель не абсолютно уверен, что они разделяют ту же строку цифр доступа частной сети с локальным объектом, он НЕ ДОЛЖЕН использовать номер плана набора (локальный телефонный номер либо номер, уточнённый локальным контекстом), так как результат может быть неверным. Вместо этого СЛЕДУЕТ использовать глобальный номер, а если это невозможно — частный контекст в качестве последнего средства. Если локальный объект не поддерживает набор в частную сеть, указанную этим контекстом, запрос ДОЛЖЕН быть отклонён. Если поддерживает, он будет использовать строку цифр доступа, подходящую для его местоположения.
Note that the use of <area-specifier> is orthogonal to use of the telephony service provider parameter (see 2.5.10); it qualifies the phone number, whilst the <service-provider> parameter indicates the carrier to be used for the call attempt.
Обратите внимание, что использование <area-specifier> ортогонально использованию параметра поставщика услуг телефонии (см. раздел 2.5.10); он квалифицирует телефонный номер, тогда как параметр <service-provider> указывает оператора, который должен использоваться для попытки вызова.
For example, a large company may have private network interconnections between its sites, as well as connections to the Global Switched Telephone Network. A phone number may be given in "public network" form, but with a <service-provider> indicating that the call should be carried over the corporate network.
Например, крупная компания может иметь частные сетевые соединения между своими площадками, а также соединения с глобальной коммутируемой телефонной сетью. Телефонный номер может быть указан в форме «публичной сети», но с <service-provider>, указывающим, что вызов должен быть передан должен быть передан по корпоративной сети.
Conversely, it would be possible to represent a phone number in private network form, with a private context to indicate this, but indicate a public telephony service provider. This would request that the user agent convert the private network number plan address into a form that can be carried using the selected service provider.
Наоборот, можно было бы представить телефонный номер в форме частной сети с частным контекстом, указывающим это, но указать публичного поставщика услуг телефонии. Это потребовало бы от пользовательского агента преобразовать адрес плана нумерации частной сети в форму, с которой можно выполнить вызов с использованием выбранного поставщика услуг.
Any telephone number MUST contain at least one <phonedigit> or <dtmf-digit>, that is, subscriber numbers consisting only of pause characters are not allowed.
Любой телефонный номер ДОЛЖЕН содержать хотя бы один <phonedigit> или <dtmf-digit>, то есть абонентские номера, состоящие только из символов паузы, не допускаются.
International numbers MUST begin with the "+" character. Local numbers MUST NOT contain that character. International numbers MUST be written with the country (CC) and national (NSN) numbers as specified in [E.123] and [E.164]. International numbers have the property of being totally unambiguous everywhere in the world if the local entity is properly configured.
Международные номера ДОЛЖНЫ начинаться с символа «+». Локальные номера НЕ ДОЛЖНЫ содержать этот символ. Международные номера ДОЛЖНЫ записываться с кодом страны (CC) и национальным номером (NSN), как указано в [E.123] и [E.164]. Международные номера обладают свойством быть полностью однозначными везде в мире, если локальный объект настроен должным образом.
Local numbers MAY be used if the number only works from inside a certain geographical area or a network. Note that some numbers may work from several networks but not from the whole world - these SHOULD be written in international form, with a set of <area- specifier> tags and optional <service-provider> parameters. URLs containing local phone numbers should only appear in an environment where all local entities can get the call successfully set up by passing the number to the dialing entity "as is". An example could be a company intranet, where all local entities are located under a the same private telephone exchange. If local phone numbers are used, the document in which they are present SHOULD contain an indication of the context in which they are intended to be used, and an appropriate <area-specifier> SHOULD be present in the URL.
Локальные номера МОГУТ использоваться, если номер работает только изнутри определённой географической области или сети. Обратите внимание, что некоторые номера могут работать из нескольких сетей, но не во всём мире — их СЛЕДУЕТ записывать в международной форме с набором тегов <area-specifier> и необязательными параметрами <service-provider>. URL, содержащие локальные телефонные номера, должны появляться только в среде, где все локальные объекты могут успешно установить вызов, передав номер наборному объекту «как есть». Примером может быть корпоративная интранет-сеть, где все локальные объекты находятся под одной частной телефонной станцией. Если используются локальные телефонные номера,
In some regions, it is popular to write phone numbers using alphabetic characters which correspond to certain numbers on the telephone keypad. Letters in <dtmf-digit> characters do not have anything to do with this, nor is this method supported by these URL schemes.
В некоторых регионах популярно писать телефонные номера с использованием буквенных символов, соответствующих определённым цифрам на телефонной клавиатуре. Буквы в символах <dtmf-digit> не имеют к этому никакого отношения, и этот метод не поддерживается данными схемами URL.
It should also be noted that implementations MUST NOT assume that telephone numbers have a maximum, minimum or fixed length, or that they would always begin with a certain number. Implementors are encouraged to familiarize themselves with the international standards.
Также следует отметить, что реализации НЕ ДОЛЖНЫ предполагать, что телефонные номера имеют максимальную, минимальную или фиксированную длину либо что они всегда начинаются с определённой цифры. Разработчикам рекомендуется ознакомиться с международными стандартами.
2.5.3. Separators in phone numbers
2.5.3. Разделители в телефонных номерах
All <visual-separator> characters MUST be ignored by the local entity when using the URL. These characters are present only to aid readability: they MUST NOT have any other meaning. Note that although [E.123] recommends the use of space (SP) characters as the separators in printed telephone numbers, spaces MUST NOT be used in phone numbers in URLs as the space character cannot be used in URLs without escaping it.
Все символы <visual-separator> ДОЛЖНЫ игнорироваться локальным объектом при использовании URL. Эти символы присутствуют только для облегчения чтения: они НЕ ДОЛЖНЫ иметь никакого иного значения. Обратите внимание, что хотя [E.123] рекомендует использовать символы пробела (SP) в качестве разделителей номерах, пробелы НЕ ДОЛЖНЫ использоваться в телефонных номерах в URL, поскольку символ пробела нельзя использовать в URL без экранирования.
2.5.4. Converting the number to the local numbering scheme
2.5.4. Преобразование номера в локальную схему нумерации
After the telephone number has been extracted, it can be converted to the local dialing convention. (For example, the "+" character might be replaced by the international call prefix, or the international and trunk prefixes might be removed to place a local call.) Numbers that have been specified using <local-phone> or <fax-local-phone> MUST be used by the local entity "as is", without any conversions, unless the local entity decides to utilize the information in an optional <service-provider> parameter.
После извлечения телефонного номера он может быть преобразован в местное соглашение о наборе. (Например, символ «+» может быть заменён международным префиксом вызова, либо международный и междугородний префиксы могут быть удалены для местного вызова.) Номера, указанные с использованием <local-phone> или <fax-local-phone>, ДОЛЖНЫ использоваться локальным объектом «как есть», без каких-либо преобразований, если только локальный объект не решит использовать информацию из необязательного параметра <service-provider>.

2.5.6. Pauses in dialing and post-dial sequence
2.5.6. Паузы при наборе и в последовательности постдозвона
A local phone number or a post-dial sequence may contain <pause- character> characters which indicate a pause while dialing ("p"), or a wait for dial tone ("w").
Локальный телефонный номер или последовательность постдозвона могут содержать символы <pause-character>, указывающие паузу при наборе («p») или ожидание сигнала ответа станции («w»).
Local entities MAY support this method of dialing, and the final interpretation of these characters is left to the local entity. It is RECOMMENDED that the length of each pause is about one second.
Локальные объекты МОГУТ поддерживать этот метод набора, и окончательная интерпретация этих символов оставлена на усмотрение локального объекта. РЕКОМЕНДУЕТСЯ, чтобы длительность каждой паузы составляла около одной секунды.
If it is not supported, local entities MUST ignore everything in the dial string after the first <pause-character> and the user SHOULD be notified. The user or the local entity MAY opt not to place a call if this feature is not supported and these characters are present in the URL.
Если это не поддерживается, локальные объекты ДОЛЖНЫ игнорировать всё в наборной строке после первого <pause-character>, и пользователь ДОЛЖЕН быть уведомлён. Пользователь или локальный объект МОЖЕТ принять решение не выполнять вызов, если эта функция не поддерживается, а эти символы присутствуют в URL.
Any <dtmf-digit> characters and all dial string characters after the first <pause-character> or <dtmf-digit> SHOULD be sent to line using DTMF (Dual Tone Multifrequency) in-band signaling, even if dialing is done using direct network signaling (a digital subscriber loop or a mobile phone). If the local infrastructure does not support DTMF codes, the local entity MAY opt to use pulse dialing. However, it should be noted that certain services which are controlled using DTMF tones cannot be controlled with pulse dialing. If pulse dialing is used, the user SHOULD be notified.
Любые символы <dtmf-digit> и все символы наборной строки после первого <pause-character> или <dtmf-digit> СЛЕДУЕТ передавать в линию с использованием внутриполосной сигнализации DTMF, даже если набор выполняется посредством прямой сетевой сигнализации (цифровая абонентская линия или мобильный телефон). Если локальная инфраструктура не поддерживает коды DTMF, локальный объект МОЖЕТ выбрать использование импульсного набора. Однако следует отметить, что некоторые службы, управляемые тонами DTMF, не могут управляться импульсным набором. Если используется импульсный набор, пользователь ДОЛЖЕН быть уведомлён.
2.5.7. ISDN subaddresses
2.5.7. Субадреса ISDN
A phone number MAY also contain an <isdn-subaddress> which indicates an ISDN subaddress. The local entity SHOULD support ISDN subaddresses. These addresses are sent to the network by using a method available to the local entity (typically, ISDN subscribers send the address with the call setup signalling). If ISDN subaddressing is not supported by the caller, <isdn-subaddress> MUST be ignored and the user SHOULD be notified. The user or the local entity MAY opt not to place a call if this feature is not supported.
Телефонный номер МОЖЕТ также содержать <isdn-subaddress>, который указывает субадрес ISDN. Локальному объекту СЛЕДУЕТ поддерживать субадреса ISDN. Эти адреса передаются в сеть с использованием метода, доступного локальному объекту (обычно абоненты ISDN передают адрес вместе с сообщением установления вызова). Если субадреса не поддерживаются, они ДОЛЖНЫ игнорироваться, а пользователь ДОЛЖЕН быть уведомлён.

Факсимильный номер МОЖЕТ также содержать <t33-subaddress>, который указывает начало субадреса T.33 [T.33]. Локальным объектам СЛЕДУЕТ это поддерживать. <modem-params> indicate the minimum compliance required from the local entity to be able to connect to the remote entity. This is typically the fastest and/or the most reliable modem type supported by the modem pool. The local entity can use this information to select the best number from a group of modem URLs. There can be several recommended modem types, which are equally desirable from the modem pool's point of view. <recommended-params> MAY NOT conflict with <modem-params>. Однако если URL указывает V.32 как минимально приемлемый,

Эта функция присутствует потому, что пулы модемов часто имеют отдельные номера для медленных и быстрых модемов, либо разные номера для аналоговых и ISDN-соединений, либо могут использовать проприетарные модемы, несовместимые со стандартами. 2.7. Rationale behind the syntax
2.7. Обоснование синтаксиса
2.7.1. Why distinguish between call types?
2.7.1. Почему различаются типы вызовов?
URLs locate resources, which in this case is some telecommunications equipment at a given phone number. However, it is not necessarily enough to know the subscriber number in order to successfully communicate with that equipment. Digital phone networks distinguish between voice, fax and data calls (and possibly other types of calls, not discussed in this specification). To be able to successfully connect to, say, a fax machine, the caller may have to specify that a fax call is being made. Otherwise the call might be routed to the voice number of the subscriber. In this sense, the call type is an integral part of the 'location' of the target resource. The reason to have the call type in the scheme specifier is to make the URL simple to remember and use. Making it a parameter, much like the way modem parameters are handled now, will substantially reduce the human readability of this URL.
URL адресуют ресурсы, в данном случае — некое телекоммуникационное оборудование с заданным телефонным номером. Однако знать абонентский номер не всегда достаточно для успешной связи с этим оборудованием. Цифровые телефонные сети различают голосовые вызовы, факсимильные вызовы и вызовы передачи данных (и, возможно, другие типы вызовов, не рассматриваемые в настоящей спецификации). Чтобы успешно подключиться, скажем, к факсимильному аппарату, вызывающий может быть обязан указать, что выполняется факсимильный вызов. Иначе вызов может быть направлен на голосовой номер абонента. В этом смысле тип вызова является неотъемлемой частью «местоположения» целевого ресурса. Причина иметь тип вызова в спецификаторе схемы состоит в том, чтобы сделать URL простым для запоминания и использования. Превращение его в параметр, подобно тому, как сейчас обрабатываются параметры модема, существенно снизило бы удобочитаемость этого URL для человека.
2.7.2. Why "tel" is "tel"?
2.7.2. Почему «tel» — это «tel»?
There has been discussion on whether the scheme name "tel" is appropriate. To summarize, these are the points made against the other proposals.
Было обсуждение о том, уместно ли имя схемы «tel». В итоге, вот аргументы, высказанные против других предложений.
callto URL schemes locate a resource and do not specify an action to be taken. telephone Too long. Also, "tel" considered to be a more international form. phone Was countered on the basis that "tel" is more internationally acceptable.
callto — схемы URL адресуют ресурс и не указывают действие, которое нужно выполнить. telephone — слишком длинно. Кроме того, «tel» считается более интернациональным и широко используемым сокращением.
2.7.3. Why to use E.164-style numbering?
2.7.3. Почему используется нумерация в стиле E.164?
E.164 refers to international telephone numbers, and the string of digits after the country code is usually a national matter. In any case, phone numbers are usually written as a simple string of numbers everywhere. Because of this, the syntax in this specification is intuitively clear to most people. This is the usual way to write phone numbers in business cards, advertisements, telephone books and so on.
E.164 относится к международным телефонным номерам, а строка цифр после кода страны обычно является национальным делом. В любом случае телефонные номера повсеместно записываются как простая строка цифр. Из-за этого синтаксис в настоящей спецификации интуитивно понятен и совпадает с общепринятой практикой набора номеров.
It should be noted that phone numbers may have 'hierarchical' characteristics, so that one could build a 'forest' of phone numbers with country codes as roots, area codes as branches and subscriber numbers as leaves. However, this is not always the case. Not all areas have area codes; some areas may have different area codes depending on how one wants to route the call; some numbers must always be dialled "as is", without prepending area or country codes (notably emergency numbers); and area codes can and do change.
Следует отметить, что телефонные номера могут иметь «иерархические» характеристики, так что можно было бы построить «лес» телефонных номеров с кодами стран в качестве корней, кодами областей в качестве ветвей и абонентскими номерами в качестве листьев. Однако это не всегда так. Не во всех областях есть коды областей; некоторые области могут иметь разные коды областей в зависимости от того, как нужно маршрутизировать вызов; некоторые номера всегда должны набираться «как есть», без добавления кодов области или страны (в частности, экстренные номера); и коды областей могут и действительно меняются.
Usually, if something has a hierarchical structure, the URL syntax should reflect that fact. These URLs are an exception.
Обычно, если что-то имеет иерархическую структуру, синтаксис URL должен это отражать. Эти URL являются исключением.
Also, when writing the phone number in the form described in this specification, the writer does not need to know which part of the number is the country code and which part is the area code. If a hierarchical URL would be used (with a "/" character separating the parts of the phone numbers), the writer of the URL would have to know which parts are which. Finally, when phone numbers are written in the international form as specified here, they are unambiguous and can always be converted to the local dialing convention, given that the user agent has the knowledge of the local country and area codes.
Кроме того, при записи телефонного номера в форме, описанной в настоящей спецификации, писателю не нужно знать, какая часть номера является кодом страны, а какая — кодом области. Если бы использовался иерархический URL (с символом «/», разделяющим части телефонного номера), автору URL потребовалось бы заранее знать структуру номера. Наконец, когда телефонные номера записаны в международной форме, как указано здесь, они однозначны и всегда могут быть преобразованы в местное соглашение о наборе при условии, что пользовательский агент знает местные коды страны и области.
2.7.4. Not everyone has the same equipment as you
2.7.4. Не у всех такое же оборудование, как у вас
There are several ways for the subscriber to dial a phone number:
Существует несколько способов набора телефонного номера абонентом:
- By pulse dialing. Typically old telephone exchanges. Usually this dialing method has only to be used to set up the call; after connecting to the remote entity, <post-dial> can be sent to the line using DTMF, because it will typically be processed by the remote entity, not the telephone network.
- Импульсным набором. Обычно старые телефонные станции. Как правило, этот метод набора должен использоваться только для установления соединения; после подключения к удалённому объекту <post-dial> может быть передан в линию с использованием DTMF, поскольку он обычно будет обрабатываться удалённым объектом, а не телефонной станцией.
- By DTMF. These are the 'beeps' that you hear when you dial on most phones.
- С помощью DTMF. Это те «пикающие» звуки, которые вы слышите при наборе на большинстве телефонов.
- By direct network signalling. ISDN subscribers and mobile phone users usually have this. There is no dial tone (or if there is, it is generated locally by the equipment), and the number of the called party is communicated to the telephone network using some network signalling method. After setting up the call, <post-dial> sequences are usually sent using DTMF codes.
- Прямой сетевой сигнализацией. Абоненты ISDN и пользователи мобильных телефонов обычно имеют это. Зуммера ответа станции нет (или, если он есть, он генерируется локально оборудованием), а номер вызываемой стороны передаётся телефонной сети с помощью некоторого сообщения сетевой сигнализации.
2.7.5. Do not confuse numbers with how they are dialled
2.7.5. Не путайте номера с тем, как они набираются
As an example, +123456789 will be dialled in many countries as 00123456789, where the leading "00" is a prefix for international calls. However, if a URL contains a local phone number 00123456789, the user-agent MUST NOT assume that this number is equal to a global phone number +123456789. If a user-agent received a telephony URL with a local number in it, it MUST make sure that it knows the context in which the local phone number is to be processed, or else the number MUST NOT be used. Equally, anyone sending a telephony URL MUST take into consideration that the recipient may have insufficient information about the phone number's context.
Например, +123456789 во многих странах будет набираться как 00123456789, где ведущие «00» — префикс международных вызовов. Однако если URL содержит локальный телефонный номер 00123456789, пользовательский агент НЕ ДОЛЖЕН предполагать, что этот номер равен глобальному телефонному номеру +123456789. Если пользовательский агент получил телефонный URL с локальным номером, он ДОЛЖЕН удостовериться, что знает контекст, в котором этот локальный телефонный номер должен обрабатываться, иначе номер НЕ ДОЛЖЕН использоваться. Аналогично любой отправитель телефонного URL ДОЛЖЕН учитывать, что у получателя может быть недостаточно информации о контексте телефонного номера.

Это примеры рекомендуемого использования данного URL в документах HTML.

5. Security Considerations
5. Вопросы безопасности
It should be noted that the local entity SHOULD NOT call out without the knowledge of the user because of associated risks, which include
Следует отметить, что локальному объекту НЕ СЛЕДУЕТ выполнять вызов без ведома пользователя из-за связанных с этим рисков, к которым относятся
- call costs (including long calls, long distance calls, international calls and premium rate calls, or calls which do not terminate due to <post-dial> sequences that have been left out by the local entity)
- стоимость вызова (включая долгие вызовы, междугородние вызовы, международные вызовы и вызовы по повышенному тарифу, либо вызовы, которые не завершаются из-за последовательностей <post-dial>, пропущенных локальным объектом);
- wrong numbers inserted on web pages by malicious users, or sent via e-mail, perhaps in direct advertising
- неверные номера, вставленные на веб-страницы злоумышленниками или отправленные по электронной почте, возможно в целях прямой рекламы;
- making the user's phone line unavailable (off-hook) for a malicious purpose
- занятие телефонной линии пользователя (снятие трубки) в злонамеренных целях;
- opening a data call to a remote host, thus possibly opening a back door to the user's computer
- установление вызова передачи данных к удалённому хосту, что может открыть лазейку в компьютер пользователя;
- revealing the user's (possibly unlisted) phone number to the remote host in the caller identification data, and correlating the local entity's phone number with other information such as the e-mail or IP address
- раскрытие телефонного номера пользователя (возможно, не внесённого в справочник) удалённому хосту в данных идентификации вызывающего, а также сопоставление телефонного номера локального объекта с другой информацией, такой как адрес электронной почты или IP-адрес;
- using the same local number in different contexts, in which the number may have a different meaning
- использование одного и того же локального номера в разных контекстах, в которых номер может иметь разное значение.
All of these risks MUST be taken into consideration when designing the local entity. The local entity SHOULD have some mechanism that the user can use to filter out unwanted numbers. The local entity SHOULD NOT use rapid redialing of the number if it is busy to avoid the congestion of the (signaling) network. Also, the local entity SHOULD detect if the number is unavailable or if the call is terminated before the dialing string has been completely processed (for example, the call is terminated while waiting for user input) and not try to call again, unless instructed by the user.
Все эти риски ДОЛЖНЫ приниматься во внимание при проектировании локального объекта. Локальный объект ДОЛЖЕН иметь некий механизм, позволяющий пользователю отфильтровывать нежелательные номера. Локальному объекту НЕ СЛЕДУЕТ использовать быстрый повторный набор номера при занятости, чтобы избежать перегрузки (сигнальной) сети. Также локальному объекту СЛЕДУЕТ обнаруживать, недоступен ли номер или был ли вызов завершён до полной обработки наборной строки (например, вызов завершён во время ожидания ввода пользователя), и не пытаться звонить снова, если только пользователь не дал указания.
